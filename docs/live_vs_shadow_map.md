# Phase 14A - Live vs Shadow Decision Map

This document maps CourtVision decision layers after Phase 13C/13D. Its purpose is to separate layers that affect daily operator picks, Kelly staking, and final operator decisions from layers that are shadow, diagnostic, reporting, or research only.

Scope note: this is an audit document only. It does not change prediction, scoring, selection, Kelly, grading, odds normalization, or any production gate.

## 1. Live Pick-Affecting Layers

In this document, "daily picks" means the operator `elite_board` artifact. A layer is live pick-affecting if it can admit, block, remove, replace, or alter rows that reach the daily elite board. Some layers also affect the `full_market_board`; those cases are called out separately.

| Layer | File and function/class | What it does | Output field or rejection reason | Affects |
| --- | --- | --- | --- | --- |
| Live market gate / live line gate | `courtvision/selection/operator_boards.py` - `build_operator_boards` | Keeps only rows that are live-market eligible: `is_live_market` must be true, `synthetic_line` must be false, and the row must have a live-market/sportsbook qualification source. Milestone markets are also filtered out. | `selection_rejection_reason`: `selection_not_live_market_eligible`, `selection_live_gate_missing_qualification_reason`, `selection_live_gate_filtered`, `unsupported_milestone_market` | Elite board and full market board. Kelly is affected indirectly because Kelly is built from elite rows. |
| Game status gate | `courtvision/runtime_selection.py` - `game_status_ineligibility_reason`, `is_game_bettable`; `courtvision/runtime_audit.py` - `get_elite_rejection_reason`, `projected_kelly_skip_reason`; package pipeline elite selection in `courtvision/pipeline/predict_pipeline.py` | Blocks games that are final, in progress, postponed, locked, or otherwise not bettable outside research mode. | Elite rejection reasons: `elite_reject_game_final`, `elite_reject_game_in_progress`, `elite_reject_game_postponed`, `elite_reject_game_locked`, `elite_reject_game_not_bettable`. ## 2. Kelly-Affecting Layers

Kelly staking is generated from the operator elite board, not from the full-market board. The primary staking script is `scripts/run_kelly_stakes.py`, with sizing logic in `courtvision/betting/kelly.py`.

| Layer | File and function/class | What it does | Output field or reason | Affects |
| --- | --- | --- | --- | --- |
| Elite-board-only input | `scripts/run_kelly_stakes.py` | Reads `outputs/runtime/operator/elite_board_<DATE>.csv`. If elite is empty, the script treats the run as non-stakeable rather than manufacturing stake rows from full market. | Empty-board fatal path; no valid stake rows should be treated as generated bets. | Kelly only. |
| `player_points`-only Kelly lock | `scripts/run_kelly_stakes.py` - `_build_stake_row` | Blocks staking for any market where `market_type != "player_points"`. | `kelly_eligible=false`, `skip_reason=kelly_points_only_market_lock`. | Kelly only. |
| Quarter-Kelly sizing | `courtvision/betting/kelly.py` - `compute_kelly_fraction`; `scripts/run_kelly_stakes.py` | Converts edge, decimal odds, and confidence into a stake fraction. It applies a confidence floor, quarter-Kelly multiplier, and maximum stake cap. | Zero/skip reasons include `confidence_below_min(0.55)`, `non_positive_edge`, `kelly_returned_zero`. Stake fields include calculated fraction/dollars. | Kelly sizing only. |
| Directional-edge Kelly input (current Kelly layer; no explicit `Phase 13D` marker found in tracked source) | `scripts/run_kelly_stakes.py` - `EDGE_COLUMN_PREFERENCE`, `_find_edge_column`, `_build_stake_row`; `courtvision/betting/kelly.py` - `compute_kelly_fraction` | Kelly requires one edge input column, preferring `side_edge_pct`, then `edge_pct`, then `edge`. The selected value must be positive before sizing is attempted. | Missing edge abort/skip paths include `missing_<edge_col>`; non-positive edge yields `skip_reason=non_positive_edge`; positive edge feeds stake sizing. | Kelly eligibility and stake sizing. |
| Daily exposure cap | `scripts/run_kelly_stakes.py` | Caps total daily exposure and proportionally scales eligible stake fractions when raw exposure exceeds the configured limit. | `exposure_scale_factor`; capped/scaled stake fraction and stake amount fields. | Kelly sizing only. |
| Manual review and HOLD logic | `scripts/run_kelly_stakes.py` - `_build_stake_row`; edge containment metadata from review/control artifacts | Converts manual review and edge-containment HOLD metadata into operator instructions. Edge-containment HOLD blocks staking. Generic `manual_review_required` produces review status and operator action, but should not be assumed to remove the row unless the Kelly row says it is ineligible or held. | `manual_review_required`, `review_status`, `stake_policy`, `recommended_action`, `operator_action`, `operator_note`, `skip_reason=edge_containment_hold_for_review`. | Kelly and operator decision. |
| High-caution OVER skip | `scripts/run_kelly_stakes.py` - `_build_stake_row`; `courtvision/runtime_audit.py` - `projected_kelly_skip_reason` | Prevents Kelly staking on high-caution OVER rows. The elite context gate usually removes the most dangerous conflicted OVERs first, but Kelly has a defensive skip too. | `skip_reason=context_high_caution_over`; projected metadata `kelly_projected_skip_reason=context_high_caution_over`. | Kelly. Elite can also be affected by the context safety gate. |
| `review_before_bet` handling | `scripts/write_operator_card.py` - `_action_value`, `_with_kelly_review_fields`; `scripts/run_kelly_stakes.py` review fields | Marks rows as requiring review before a wager is placed. This is an operator-action signal, not proof the row was removed from elite or that no Kelly row exists. | `review_before_bet`, `recommended_action=REVIEW_BEFORE_BET`, `operator_action=DO_NOT_BET_UNTIL_REVIEWED`, `final_decision=REVIEW REQUIRED`. | Operator decision and Kelly review interpretation. |
| Stale or invalid odds handling | `courtvision/runtime_selection.py` odds freshness gate; `scripts/run_kelly_stakes.py` numeric odds validation | Stale timestamps can block elite and create projected Kelly skips. The Kelly script itself validates the odds values used for sizing, including missing American odds and invalid decimal odds. | Elite/projection: `elite_reject_odds_stale`, `odds_stale`. Kelly: `missing_or_invalid_odds`, `non_positive_decimal_odds`. | Elite, Kelly metadata, and Kelly staking validity. |
| Medium neutral OVER dampener | `scripts/run_kelly_stakes.py` - `_medium_neutral_over_dampener` | Reduces stake size for eligible OVER rows with medium caution and neutral context alignment. | Dampened stake amount/fraction; dampener metadata if present in the row output. | Kelly sizing only. |

## 3. Review-Only Layers

Review-only fields do not necessarily remove a pick. They change how an operator should interpret the row before placing a bet.

| Field/layer | File and function/class | Interpretation |
| --- | --- | --- |
| `manual_review_required` | `courtvision/reporting/same_opponent_rematch.py` - `annotate_same_opponent_rematches`; consumed by `scripts/write_daily_summary.py`, `scripts/write_operator_card.py`, and `scripts/run_kelly_stakes.py` | The row requires human review. Same-opponent UNDER review is explicitly diagnostic/manual-review only; it does not automatically remove the pick. In Kelly, generic manual review can coexist with a stake row, so the operator action must be honored. |
| `review_before_bet` | `scripts/write_operator_card.py` - `_action_value`, `_with_kelly_review_fields` | Tells the operator not to treat the row as automatic. It contributes to `REVIEW REQUIRED` on the operator card. |
| `recommended_action` | `scripts/run_kelly_stakes.py`; edge containment review/control reporting | Operator instruction such as `OK_TO_CONSIDER`, `REVIEW_BEFORE_BET`, or `DO_NOT_BET_UNTIL_REVIEWED`. The instruction should be followed even if a row is present in elite or Kelly output. |
| Directional-edge operator display | `scripts/write_operator_card.py` - `_edge_value`, `_pick_rows` | Displays `directional_edge` when available, otherwise `edge`, on the operator card. This helps operators inspect edge direction/size but does not itself remove a row. |
| `same_opponent_under_warning` | `courtvision/reporting/same_opponent_rematch.py` | Flags player-points UNDER candidates where same-opponent history raises a warning. It is a manual-review signal, not an automatic suppression gate. |
| Operator card `final_decision` | `scripts/write_operator_card.py` - `_final_decision` | Final run-level decision. It is not a model score; it summarizes artifact health, provider safety, elite count, and review/HOLD counts. |
| Kelly review warnings | `scripts/run_kelly_stakes.py`; `scripts/write_operator_card.py` | Fields such as `review_status`, `stake_policy`, `operator_action`, `operator_note`, `kelly_manual_review_required`, and `review_policy_hold` modify whether the operator should act. They can make a Kelly row non-actionable even when a stake amount exists. |

## 5. Ambiguous Or Inconsistent Layers

These are the main places where the language or artifact names can be misread.

- Game context is described as passive for projection math, and the daily summary says context preview signals do not alter projections. That is true for projections. It is not true for final elite/Kelly safety, because high-caution conflicted OVER context can remove final elite candidates and high-caution OVER rows can be skipped by Kelly.
- The `player_points` strong-OVER calibration guard is diagnostic-looking because affected rows can remain in the full-market board, but it is live for elite and Kelly eligibility.
- `projected_kelly_skip_reason` is metadata produced before or alongside final Kelly generation. It is useful, but the authoritative staking result is the row in `kelly_stakes` with its `kelly_eligible`, `skip_reason`, stake, and review fields.
- Edge-containment review artifacts are mostly review/shadow, but HOLD control metadata is live for Kelly staking. It blocks staking, not board inclusion.
- Full-market readiness gates are live for admitting candidates to the full-market board, while full-market performance/readiness reports are diagnostic. Do not confuse the gate with the report.
- Odds freshness is a live elite/projected-Kelly gate. The Kelly script separately validates odds values for stake math; it does not directly re-run the `odds_updated_at` freshness check.
- Calibration reports are diagnostic. Player-points recalibration in the prediction pipeline is not diagnostic if the pipeline is explicitly run in enabled recalibration mode.
- Phase-label audit: tracked source contains an explicit `Phase 13C` readiness string in `courtvision/reporting/player_points_inflation_audit.py`, but no explicit `Phase 13D` code label was found. The live directional-edge behavior is therefore mapped above by actual file/function names rather than by an inferred phase label.

## 6. Operator Decision Map

The operator card decision is produced by `scripts/write_operator_card.py` in `_final_decision`.

| Final decision | Conditions that cause it | Should the user place a bet? | Can Kelly rows exist? | Is manual review required? |
| --- | --- | --- | --- | --- |
| `BETTABLE` | Required artifacts are present, provider/date/run-health checks are safe, at least one elite row exists, and no manual-review, `review_before_bet`, or Kelly HOLD counts are present. | The row set is eligible for betting consideration. Still verify live sportsbook line and price before placing any wager. | Yes. | No run-level manual review flag is present. |
| `REVIEW REQUIRED` | Elite candidates exist, but at least one manual-review, `review_before_bet`, or Kelly HOLD count is present. | Do not place automatically. Review the flagged row(s), live line, and operator action first. | Yes, including rows that may show stake amounts. Kelly output is not automatic authorization when review flags exist. | Yes. |
| `NO BET` | The run is otherwise healthy enough to interpret, but `elite_count <= 0`. | No. There is no current elite bettable board. | Usually no actionable Kelly rows. Any stale or leftover stake file should not override the empty elite board. | Not necessarily; the decision is driven by no elite picks. |
| `DEGRADED` | Required artifacts are missing, provider/live status is unsafe, date isolation/output validation fails, or quality run health is `ERROR_OR_INCOMPLETE` or starts with `DEGRADED`. | No. Treat the run as operationally unsafe. | Possibly, but they are not trustworthy until the degraded condition is resolved. | Operational review is required before betting. |

## Do Not Misread These Signals

- Full-market candidates are not bettable by default.
- Kelly rows are not automatic bets when review flags exist.
- High model edge does not mean bettable.
- Shadow hit rate does not mean live profitability.
- Diagnostic layers should not be marketed as production accuracy.
- Power Rating and game-strength context are currently observation/diagnostic in the audited paths.
- Review-only warnings can change the operator action without removing a row from elite.
- If the operator card says `DEGRADED`, no downstream artifact should be used to justify a bet until the degradation is resolved.
